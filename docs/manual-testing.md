# Ручная проверка bdv

Что не покрыто автотестами: реальный терминал, темы, буфер обмена, мышь, настоящий `bd`. Перед проверкой: `make build`, дальше запускайте `./bdv` (или `bdv` после `make install`) из папки проекта. Ничего не пишите в проекты через `bd`, кроме четырёх пунктов: про агента в «Автообновлении», про настоящий комментарий в «Комментариях», про настоящий `bd init` в «Инициализации» и про запись настроек в «Настройках bd», и все — только в своём тестовом (одноразовом) проекте.

Интерфейс по умолчанию английский, поэтому ниже строки интерфейса приведены по-английски. Русский интерфейс проверяется запуском `BDV_LANG=ru ./bdv` (см. «Язык»): там те же строки по-русски.

## Основной просмотр (тестовый проект с вложенными задачами и комментариями)

- [ ] Дерево: открытые сверху, закрытые и события скрыты, ветки раскрываются и сворачиваются.
- [ ] Карточка с markdown: заголовки, списки, код отображаются, длинные строки переносятся.
- [ ] Комментарии у задачи с комментариями (например `demo-app-2e9.6`) показаны в карточке.
- [ ] `c` показывает и скрывает закрытые задачи без паузы; в статус-строке появляется и пропадает `closed`.
- [ ] `/кон` фильтрует по кириллице и латинице, `Enter` закрепляет (в статус-строке `filter: кон`), `Esc` сбрасывает.
- [ ] Цифры `1`–`9` переходят по связям в карточке из любого фокуса.
- [ ] `y` копирует ID: в соседнем окне вставьте (`Cmd+V`), ID совпадает; в статус-строке `copied: <id>`.
- [ ] Ресайз до 70 колонок: узкий режим (`Enter` открывает карточку, `Esc` возвращает), обратно к двум панелям.
- [ ] Мышь: колесо мыши прокручивает панель под курсором (над деревом двигает выбор); клик ничего не делает.
- [ ] `bdv <id вложенной задачи>` (например `bdv demo-app-2e9.6`) открывается сразу на задаче, предки и её группа раскрыты.
- [ ] Очень длинный заголовок (любой длиннее панели): в карточке заголовок переносится на несколько строк и читается целиком, ни одна строка шапки не обрезана `…`.
- [ ] Ресайз сразу после запуска: запустите `bdv`, в первые секунды несколько раз измените размер окна и быстро нажмите `j` три раза. Выбор сдвинулся ровно на три строки, нет пауз и потерянных нажатий.

## Группы по приоритету

- [ ] По умолчанию корни разложены по группам `P0`…`P4`; у заголовка группы жирное `P<n>` в цвете приоритета и число видимых задач (`▾ P1 · 3`). У задач внутри группы `P<n>` в строке нет, у подзадач с другим приоритетом есть.
- [ ] `p` выключает группы (в статус-строке `no groups`, у каждой строки свой `P<n>`) и включает обратно; выбранная задача остаётся выбранной.
- [ ] Выберите заголовок группы: карточка группы показывает `3 tasks` (число видимых задач) и сводку по статусам, в рамке карточки `P1`. Сводка меняется вместе с `c`, `e` и поиском.
- [ ] Под сводкой группы секция `Tasks`: задачи группы в порядке дерева, строки `[n] <иконка> <id>  <заголовок>`, у ждущих красный `⊘` после ID. Список меняется вместе с `c`, `e`, `R` и поиском. Цифра выбирает задачу (свёрнутая группа раскрывается); номера только у первых девяти.
- [ ] Сверните группу (`h` или `Enter` на заголовке) и нажмите `r` либо дождитесь автообновления: группа осталась свёрнутой, счётчик в заголовке актуальный. Раскрытые группы остались раскрытыми.
- [ ] `h` на корневой задаче (без родителя; раскрытую ветку первое `h` сворачивает) переводит выбор на заголовок её группы; ещё раз `h` сворачивает группу.

## Короткий ID

- [ ] В проекте, где у всех задач один префикс (`demo-app-…`), дерево показывает ID без префикса (`2e9.6`), а рамка карточки, ссылки и `y` — полный ID.
- [ ] В проекте со смешанными префиксами (у задач разные `<x>-`) дерево показывает полный ID у всех задач.

## Статусы и дизайн

- [ ] Верхняя строка: имя проекта (папка с `.beads`) и сводка `◐ 2 in progress · ○ 5 open · ● 0 blocked · ✓ 21 closed`; `blocked` виден и при нуле, закрытые считаются только при `c`.
- [ ] Бейджи статусов в шапке карточки: `OPEN`, `IN PROGRESS`, `BLOCKED`, `DEFERRED`, `CLOSED` — текст бейджа читается на его фоне.
- [ ] Обе панели в скруглённых рамках, у активной `◆` перед заголовком и акцентный цвет рамки; `Tab` переносит акцент.
- [ ] Тёмная тема терминала: выделенная строка в активной панели на тёмно-синем фоне, в неактивной — на сером; красные `P0` и `●` blocked, жёлтый `◐`, ID и заголовок на выделенной строке читаются. ID на выделенной строке не приглушён.
- [ ] Светлая тема терминала: то же — выделение в активной панели на светло-голубом фоне, в неактивной на сером; `P0`, `P1`, `◐` читаются; бейдж `IN PROGRESS` чёрным по жёлтому.
- [ ] В проекте с множеством плоских задач выберите строку с `P0` или `●` blocked и проверьте читаемость в обеих темах.

## Комментарии

Проверки до настоящей записи — на фейковом `bd` или с ошибкой; настоящая запись — один раз и только в своём тестовом проекте.

- [ ] `m` на задаче открывает внизу поле `Comment on <id>:` с подсказкой `Ctrl+S send · Esc cancel`, панели над ним укоротились. На заголовке группы `m` ничего не делает, подсказки `m comment` справа в статус-строке нет.
- [ ] Набор текста: `j`, `q`, `c`, `/` и цифры идут в текст, а не в команды. Многострочный текст через `Enter`. Вставка (`Cmd+V`) текста с переводами строк Windows не даёт пустых строк между строками.
- [ ] `Esc` закрывает поле, черновик возвращается при следующем `m` на той же задаче; на другой задаче поле пустое.
- [ ] `Alt+Enter` (и быстрые `Esc`+`Enter`) не отправляют комментарий: поле остаётся открытым, текст на месте, отправляет только `Ctrl+S`. В справке `Ctrl+S  send` без упоминания `Alt+Enter`.
- [ ] Ошибка `bd` оставляет текст на месте: подложите `bd`, который падает на `comments add`
      (`mkdir -p /tmp/bd-fail && printf '#!/bin/sh\ncase "$*" in *"comments add"*) echo "Error: database is locked" >&2; exit 1;; esac\nexec %s "$@"\n' "$(command -v bd)" > /tmp/bd-fail/bd && chmod +x /tmp/bd-fail/bd`,
      затем `PATH=/tmp/bd-fail:$PATH ./bdv`). `m` → текст → `Ctrl+S`: под полем `⚠ comment not added: Error: database is locked`, текст в поле, правка работает, `Ctrl+S` отправляет снова.
- [ ] Таймаут отправки (такой же скрипт, но `sleep 60` вместо `exit 1`): через 15 с под полем `bd did not respond in 15 s; may have been saved — check comments before resending`, текст в поле, комментарии в карточке перезагружены.
- [ ] Выход во время отправки: с зависшим `bd` из предыдущего пункта `Ctrl+S`, затем сразу `Ctrl+C`. bdv выходит без паузы, и `ls $TMPDIR/bdv-comment-*` ничего не находит. То же при `kill -INT <pid bdv>` из соседнего окна.
- [ ] Настоящий `bd comments add`: в своём тестовом проекте (создайте его сами или через `bd init` из пункта «Инициализация») `m` → текст → `Ctrl+S`. Поле закрылось, в статус-строке `comment added`, комментарий появился в карточке, `bd comments <id>` в соседнем окне его показывает, `ls $TMPDIR/bdv-comment-*` пусто.

## Инициализация (`bd init`)

Сначала на фейковом `bd`, затем один настоящий запуск. Настоящий `bd init` создаёт базу на вашем Dolt-сервере, общем для всех проектов: берите одноразовое имя папки (например `bdv-init-test-<дата>`) и после проверки удалите базу средствами самого `bd` (не руками в Dolt).

- [ ] Фейковый `bd` без базы: `mkdir -p /tmp/bd-nodb && printf '#!/bin/sh\ncase "$*" in *init*) echo "Error: dolt server unreachable" >&2; exit 1;; *) echo "Error: no beads database found" >&2; exit 1;; esac\n' > /tmp/bd-nodb/bd && chmod +x /tmp/bd-nodb/bd`, затем `cd "$(mktemp -d)" && PATH=/tmp/bd-nodb:$PATH <путь>/bdv`. Сразу экран `No beads database in this project.` с подсказкой `i — initialize (bd init) · r — retry · q — quit`, без выхода.
- [ ] `i`: подтверждение `Initialize beads in <полный путь>?`, `prefix: <имя папки>`, `IDs: hash (bd default)`, `y — run bd init · c — switch IDs · n — cancel`. `c` переключает строку на `IDs: sequential 1, 2, 3` и обратно, подтверждение не закрывается. `n`, `Esc`, `j` возвращают на экран без базы; `y` на экране без базы (без `i`) ничего не делает.
- [ ] Последовательные ID на фейковом `bd` (записывает вызовы, ничего не создаёт): `mkdir -p /tmp/bd-seq && printf '#!/bin/sh\necho "$*" >> /tmp/bd-seq/calls\ncase "$*" in *list*) [ -f /tmp/bd-seq/inited ] && echo "[]" || { echo "Error: no beads database found" >&2; exit 1; };; *init*) touch /tmp/bd-seq/inited; echo "bd initialized";; esac\n' > /tmp/bd-seq/bd && chmod +x /tmp/bd-seq/bd`, затем `cd "$(mktemp -d)" && PATH=/tmp/bd-seq:$PATH <путь>/bdv` → `i` → `c` → `y`. Открылось пустое дерево; в `/tmp/bd-seq/calls` после `init` строка `config set issue_id_mode counter` (без `--readonly`), все `list` — с `--readonly`. С хешем (`i` → `y`, без `c`) строки `config` нет. Удалите `/tmp/bd-seq` между прогонами.
- [ ] Ошибка `bd config set`: в фейке добавьте `*config*) echo "Error: unknown key" >&2; exit 1;;` — после `i` → `c` → `y` видно `⚠ sequential IDs not enabled: Error: unknown key`, дерево всё равно открывается, предупреждение остаётся в статус-строке.
- [ ] `i`, `y` с тем же фейком: `initializing…`, затем снова экран без базы с `⚠ bd init failed: exit status 1` и `Error: dolt server unreachable`; `i` → `y` повторяет. `q` во время `initializing…` не выходит, `Ctrl+C` выходит сразу.
- [ ] Настоящий `bd init`: `mkdir /tmp/bdv-init-test-<дата> && cd $_ && git init && <путь>/bdv`. Экран без базы → `i` → проверьте путь и префикс → `y`. После `initializing…` на мгновение видны последние строки вывода `bd init`, затем открывается дерево `Tasks (0)` с `No tasks`, в верхней строке имя папки. В папке появился `.beads`. Затем удалите созданную базу средствами `bd` и папку.
- [ ] `BDV_LANG=ru`: те же экраны по-русски (`В этом проекте нет базы beads.`, `Инициализировать beads в …?`, `префикс: …`, `ID: хеш (по умолчанию bd)` / `ID: последовательные 1, 2, 3`, `инициализация…`, `последовательные ID не включены: …`). Окно 80x24 и 40 колонок: ничего не вылезает за край.

## Копирование и мышь (v1.2)

- [ ] На задаче с описанием: `y` → тост `copied ID: <id>`, `Y` → `copied title`, `D` → `copied description`, `M` → `copied card`. После каждой клавиши вставьте буфер (`pbpaste`): ID; заголовок; описание исходным markdown (`**`, `#`, списки целы); карточка — `# <заголовок>`, строка `` `<id>` · <статус> · P<n> · <тип> ``, `## Description`, `## Notes` (пустые секции пропущены).
- [ ] На задаче без описания `D` → `nothing to copy`, буфер прежний. На заголовке группы `y`/`Y`/`D`/`M` → `nothing to copy`.
- [ ] В поиске (`/`), в поле комментария (`m`) и в справке (`?`) клавиши `y Y D M S` не копируют и не переключают мышь: в поиске и поле они печатаются, справку закрывают.
- [ ] `S`: в статус-строке `mouse off`, мышью выделяется текст терминала, колесо панели не прокручивает и курсор дерева не двигает (bdv выключает alternate scroll, 1007). Ещё `S`: пометка пропала, колесо снова двигает курсор.
- [ ] `S`, затем `q`: в том же терминале `less` длинного файла прокручивается колесом (1007 вернулся при выходе).
- [ ] При включённом перехвате выделение работает с Shift (Ghostty, iTerm2) и с Fn (Terminal.app).
- [ ] `BDV_LANG=ru`: тосты `скопирован ID: …`, `скопирован заголовок`, `скопировано описание`, `скопирована карточка`, `нечего копировать`, пометка `мышь выкл`.
- [ ] Справка (`?`) в 80x24 на обоих языках видна целиком без прокрутки: клавиши копирования, `S` и строка про Shift/Fn+мышь.

## Зависимости (v1.2)

- [ ] В проекте, где у задачи есть открытый блокер (`bd dep add <задача> <блокер>` в своём тестовом проекте или фейковый `bd`): в строке дерева задачи `⊘` красным перед заголовком, ID на месте. В верхней строке `⊘ N waiting` после сводки статусов; без заблокированных задач счётчика нет.
- [ ] Карточка заблокированной задачи: под чипами `⊘ waiting on 1 open blocker` (или `N open blockers`), ниже секция `Blocked by`. У незаблокированной строки нет.
- [ ] Закрытая задача с открытым блокером (`c`): у неё `✓` без `⊘`, в счётчике `waiting` её нет, в карточке есть `Blocked by`, но нет строки `waiting on`; при `R` она остаётся видна.
- [ ] Блокер закрыт (или задача-блокер закрывается и проходит автообновление): `⊘` у задачи пропадает, счётчик уменьшается. Блокер, которого нет в `bd list`, считается открытым.
- [ ] `R`: в статус-строке `ready`, в дереве только незаблокированные задачи, заблокированный родитель готовой подзадачи приглушён как контекст. Вместе с `/` поиском, `p` (группы и их счётчики), `c` и `e` фильтр работает. Ещё `R` — всё вернулось.
- [ ] `R`, затем на карточке родителя цифра связи на заблокированную подзадачу: фильтр `ready` выключается, задача выбрана. Если готовых задач нет совсем — `No ready tasks — press R to show all`.
- [ ] `BDV_LANG=ru`: `⊘ N ждут`, `⊘ ждёт 1 открытого блокера`, пометка `готовые`, `Нет готовых задач — R покажет все`.
- [ ] Только чтение на реальных проектах: `bdv` в тестовом проекте с деревом и в проекте с множеством плоских задач — `⊘` стоит у задач с прямым открытым блокером; сверьте с `bd blocked` (bd может считать заблокированными и подзадачи заблокированного родителя, bdv — нет).

## Настройки bd (v1.3)

Запись проверяется **только в одноразовом проекте** (`mkdir /tmp/bdv-set && cd /tmp/bdv-set && bd init`) или с фейковым `bd` в `PATH`. В рабочих проектах — только открыть и посмотреть.

- [ ] Только чтение, тестовый проект `demo-app`: `,` — сначала `loading settings…`, затем рамка `Settings · demo-app`, секции `IDs`, `Statuses & types`, `Creating issues`, `Storage (advanced)`. `ID prefix demo-app`, незаданные значения приглушены с `(default)`. Под выбранной строкой описание и ключ (`issue_id_mode`). `Esc` — дерево на месте. Ничего не менять.
- [ ] В проекте на bd 0.59 нет строки `Auto-export JSONL`: `bd --readonly config get export.auto --json` отдаёт ответ без `location`. Внизу приглушённая строка про `BD_*` и глобальный конфиг.
- [ ] Нет и не появляется: `schema_version`, `db`, `actor`, `identity`, токенов и ключей, `sync.remote`, `federation.*`, `compact_batch_size`.
- [ ] `,` не работает в поиске (`/` — запятая уходит в запрос), в справке, в поле комментария, на экранах загрузки и без базы. Пока открыты настройки, `q`, `c`, `p`, `/`, `m`, `y` ничего не делают; `Ctrl+C` выходит.
- [ ] `ID prefix`: `Enter` и `u` ничего не делают, подсказка `change with bd rename-prefix`.
- [ ] Одноразовый проект: `Require description` — `Enter` → `create.require-description: false (default) → true`, `n` отменяет, ещё раз `Enter`, `y` — `saving…`, значение `true`; `bd config get create.require-description` подтверждает. `u` → `… → false (default)`, `y`.
- [ ] `ID mode` → `counter`: в подтверждении предупреждение `Affects new tasks only…`; после `y` строки длин хеша и вероятности коллизий пропали, дерево перечитано; `bd create` даёт последовательный ID. `u` возвращает `hash`.
- [ ] `Max nesting depth`: `Enter`, ввести `0` → `⚠ enter a number from 1 to 10`, поле открыто; `Esc` отменяет; `5` → подтверждение → `y`. `Min hash length` `9` при max 8 → `must not exceed max_hash_length (8)`.
- [ ] `Custom statuses`: `Enter` — встроенные `open, in_progress, …` приглушены; `a`, `Bad-Name` → ошибка имени, `closed` → `closed is built in`, повтор → `… is already in the list`; `qa` добавлен; создать задачу со статусом `qa` (`bd update <id> --status qa`), удалить `qa` (`x`), `Enter` → `⚠ 1 task uses qa`, `n`. `Esc` отменяет редактор целиком.
- [ ] `Dolt auto-commit` → `off`: предупреждение про незакоммиченные изменения; `Dolt auto-push` → `true`: `Needs a remote; …`. Отменить оба.
- [ ] Ошибка чтения отдельного ключа (фейковый `bd`, `config get` с ошибкой): строка `⚠ N settings could not be read · r — retry`; после починки `r` возвращает строки.
- [ ] `Max hash length` задан, `Min hash length` = 9: `u` на `Max hash length` не открывает подтверждение, под строкой `cannot reset: min_hash_length (9) must not exceed max_hash_length (8)`.
- [ ] Ошибка записи (фейковый `bd`, `config set` с кодом 14): под строкой `⚠ not saved: <первая строка>`, без управляющих символов; остальное работает.
- [ ] В 80x24 и 70 колонках на обоих языках всё в рамке, курсор при `G`/`g` виден; окно 24x7 на подтверждении — `window too small`, `y` не срабатывает. `BDV_LANG=ru`: `Настройки · …`, `(по умолчанию)`, `y — применить · любая другая клавиша — отмена`.
- [ ] Справка `?` в 80x24 на обоих языках: строка `,  bd settings` / `настройки bd`, без прокрутки.

## Спеки, вкладки, карточка группы (v1.4)

Только чтение: задачи с полями спеки и шаблоны создавайте в своём тестовом проекте.

- [ ] Под верхней строкой строка вкладок `Tasks │ Specs N │ Decisions N │ Memory │ Formulas`: активная подсвечена, пустые (`0`) приглушены. `]` и `[` переключают по кругу. В режиме поиска, в справке, в поле комментария и в настройках `[`/`]` не переключают.

## Окружение

- [ ] Пустая папка с `--db` или `BEADS_DIR` на несуществующий путь (`BEADS_DIR=/tmp/nope/.beads ./bdv`): `bd init` не предлагается, обычный экран ошибки `bd exited with an error` без клавиши `i`.
- [ ] `PATH` без `bd` (например `PATH=/usr/bin ./bdv`): `bd not found in PATH — install beads: …`, код 1.
- [ ] `bdv --help`, `bdv --version`, `bdv -x` (`unknown flag -x`, код 1).
- [ ] Зависший `bd`: подложите в `PATH` скрипт, который молчит минуту:
      `mkdir -p /tmp/bd-hang && printf '#!/bin/sh\nsleep 60\n' > /tmp/bd-hang/bd && chmod +x /tmp/bd-hang/bd`,
      затем `PATH=/tmp/bd-hang:$PATH ./bdv` в папке с `.beads`. Через 30 с вместо `Loading tasks…` экран ошибки с текстом `bd did not respond in 30 s`; `r` повторяет попытку, `q` выходит сразу, не дожидаясь `bd`.
