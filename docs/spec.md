# bdv: интерактивный просмотр задач beads в терминале

Статус: ready-for-agent · v1 · 2026-11-19

## Problem Statement

Я веду задачи в beads (`bd`) в нескольких проектах. Смотреть их сейчас неудобно:

- `bd list` печатает дерево один раз и выходит. Чтобы прочитать задачу, нужно скопировать её ID и набрать `bd show <id>`, потом вернуться к списку, и так по кругу.
- Дерево статичное: ветки нельзя свернуть, нет поиска, по умолчанию показывается только 50 задач, а в некоторых проектах дерево засоряют служебные события («State change: flow → merged»).
- Есть `bv`, но он перегружен графами, метриками и triage. Мне нужен один экран: дерево задач слева, подробности выбранной справа.
- Пока я смотрю задачи, агенты их меняют, и вывод `bd list` в терминале быстро устаревает.

## Solution

`bdv`: лёгкий TUI только для чтения поверх CLI `bd`. Запускается в папке проекта и сразу показывает:

- **слева** дерево задач по связям parent-child: открытые сверху, закрытые и служебные события скрыты, ветки сворачиваются, есть поиск;
- **справа** полную карточку выбранной задачи: метаданные, описание и заметки в markdown, родитель, дети, блокеры и комментарии. По связям можно переходить цифрами;
- **внизу** статус-строку со временем последнего обновления.

Данные обновляются сами раз в 10 секунд, выбранная задача и раскрытые ветки при этом сохраняются. ID выбранной задачи копируется в буфер одной клавишей, чтобы в соседнем окне набрать `bd update <id>`.

## User Stories

### Запуск

1. Как разработчик, я хочу запустить `bdv` в папке проекта и сразу увидеть дерево задач, чтобы не вспоминать флаги `bd list`.
2. Как разработчик, я хочу, чтобы `bdv` находил `.beads` так же, как `bd`, в текущей папке или выше, чтобы запускать его из любой подпапки проекта.
3. Как разработчик, я хочу запустить `bdv <id>` и сразу оказаться на этой задаче с раскрытыми предками, чтобы открывать задачу по ID из сообщения агента.
4. Как разработчик, я хочу передать `--db <path>`, чтобы смотреть базу вне текущей папки, как с `bd --db`.
5. Как разработчик, я хочу видеть индикатор загрузки на время первого вызова `bd` (около секунды), чтобы понимать, что программа не зависла.
6. Как разработчик, я хочу получить понятное сообщение и выход, если `bd` нет в `PATH`, чтобы сразу понять, что поставить.
7. Как разработчик, я хочу получить понятное сообщение и выход, если в папке нет `.beads`, с подсказкой `bd init`, чтобы не гадать, почему пусто.
8. Как разработчик, я хочу видеть экран ошибки с текстом stderr от `bd`, если первая загрузка упала (например, Dolt-сервер не нашёл базу), чтобы понять причину, не выходя из `bdv`.
9. Как разработчик, я хочу нажать `r` на экране ошибки и повторить загрузку, чтобы после `bd doctor` в соседнем окне не перезапускать `bdv`.

## Implementation Decisions

### Общее

- Язык Go, библиотеки Bubble Tea (цикл приложения), Lipgloss (раскладка, цвета), Bubbles (viewport, textinput, spinner), Glamour (markdown).
- Один бинарник `bdv`, модуль `github.com/nizom333/bdv`. Makefile с целями `build`, `install` (в `$(PREFIX)/bin`, по умолчанию `~/.local/bin`) и `test` (vet + тесты), версия зашивается через ldflags.
- Только чтение. `bdv` вызывает лишь читающие команды `bd`. Для страховки все вызовы идут с глобальным флагом `--readonly`.
- Источник данных только CLI `bd`. Базу Dolt, файлы `.beads` и JSONL напрямую не читаем.

### Модули

**1. Источник данных (bd-адаптер).** Глубокий модуль с узким интерфейсом: «дай все задачи», «дай подробности задачи», «дай комментарии задачи». Внутри он запускает процесс `bd`, передаёт `--db`, если он задан, разбирает JSON и превращает ненулевой код выхода в ошибку с текстом stderr. Остальной код о `bd` не знает. Контракт `bd` v0.59, проверен на реальных проектах:

- `bd list --flat --json --all -n 0` возвращает массив задач. **`--flat` обязателен**: без него `--json` игнорируется и печатается текстовое дерево. Поля: `id, title, description, notes, status, priority, issue_type, assignee, owner, labels, parent, dependencies[], dependency_count, dependent_count, comment_count, created_at, created_by, updated_at, closed_at, close_reason`. Элемент `dependencies[]`: `issue_id, depends_on_id, type` (`parent-child`, `blocks`, …).
- `bd show <id> --json` возвращает массив из одной задачи. В нём есть `dependents[]` и `dependencies[]` с полной карточкой связанной задачи и полем `dependency_type`. Комментариев там нет.
- `bd comments <id> --json` возвращает массив `{id, issue_id, author, text, created_at}`. Вызывается только при `comment_count > 0`.
- Типы зависимостей в реальных данных: `parent-child`, `blocks`, `discovered-from`. В карточке `blocks` разносится по секциям Blocked by и Blocks, остальные типы кроме `parent-child` попадают в секцию Related с подписью типа.
- Глобальный `--readonly` совместим с `list`, `show` и `comments` (проверено).
- Время ответа: `list` 0.7–1.2 с, `show` около 50 мс.
- Неизвестные поля JSON игнорируются, отсутствующие считаются пустыми, чтобы пережить мелкие изменения контракта.

**2. Модель дерева (чистая логика, без TUI).**

- Строит лес из списка задач по полю `parent`. Задача с `parent`, которого нет в выборке, становится корнем.
- Сортирует соседей: группа статуса (`in_progress` → `open` → `blocked` → `deferred` → прочие → `closed`), затем приоритет по возрастанию, затем `created_at`.
- Видимость по опциям `{showClosed, showEvents, query}`:
  - задача видна, если проходит фильтры статуса и типа или у неё есть видимый потомок; во втором случае она помечается как «контекст» и рисуется затемнённой. Отсюда же следует правило «закрытый родитель с открытыми детьми»;
  - при непустом `query` видны совпадения (подстрока ID или заголовка, сравнение через Unicode case folding) и их предки как контекст. Скрытые фильтрами задачи не совпадают.
- Множество раскрытых узлов по умолчанию: узел раскрыт, если у него есть открытый потомок. Ручные действия пользователя (раскрыл или свернул) запоминаются отдельно и при обновлении данных важнее значения по умолчанию.
- На выходе плоский список видимых строк. Строка содержит ссылку на задачу, глубину, признаки «есть дети», «раскрыт» и «контекст». При активном поиске предки совпадений раскрыты принудительно.
- Навигация: найти строку задачи, найти родителя, раскрыть путь до задачи (для `bdv <id>` и переходов по цифрам). Если задача исчезла, ближайшей видимой считается следующий сосед, затем предыдущий, затем родитель.

**3. Карточка задачи (рендер).** Функция от «задача + подробности, если загружены + комментарии + ширина» к тексту и упорядоченному списку пронумерованных ссылок. Порядок секций: шапка → Description → Notes → Parent → Children → Blocked by → Blocks → Related → Comments. Пустые секции пропускаются. Номера `[1]…[9]` раздаются связям в порядке секций. Если `bd show` ещё не пришёл, Children берутся из модели дерева, Blocked by — из `dependencies` в списке (с заголовками из того же списка), секция Blocks показывается после загрузки. Markdown рендерит Glamour с переносом по ширине панели. Стиль (`dark`, `light` или `notty`) определяется один раз до запуска TUI: опрос терминала изнутри работающей программы съедает нажатия клавиш. Результат рендера кешируется по ключу «ID + updated_at + ширина».

**4. Приложение (Bubble Tea model).** Хранит состояние: данные, модель дерева, курсор, фокус (`tree` или `detail`), режим поиска, переключатели, кеш подробностей и комментариев, состояние обновления, ошибку, размеры.

- Все вызовы `bd` идут через команды Bubble Tea асинхронно, интерфейс не блокируется.
- Таймер опроса срабатывает раз в 10 с. Если предыдущая загрузка ещё идёт, новая не стартует (флаг in-flight).
- Устаревшие ответы `show` и `comments` (пришли для задачи, которая уже не выбрана) кладутся в кеш, но не перерисовывают текущую карточку.
- После успешного `list` из кеша подробностей удаляются задачи с изменившимся `updated_at`.
- Раскладка: ширина дерева равна 40% экрана в пределах от 30 до 60 колонок, остальное занимает карточка, внизу статус-строка в одну строку. Если ширина меньше 80, показывается одна панель с переключением `Enter`/`Esc`.
- Иконки статусов совпадают с `bd list`: `○` open, `◐` in_progress, `●` blocked, `✓` closed, `❄` deferred. Цвета приоритетов: P0 красный, P1 оранжевый, P2 обычный, P3–P4 приглушённые. Все цвета адаптивные (`lipgloss.AdaptiveColor`).
- Мышь включена (cell motion), колесо прокручивает панель под курсором.
- Копирование: сначала `pbcopy`, если его нет, то OSC52. Подтверждение показывается в статус-строке примерно 2 секунды.

**5. Точка входа.**

- Разбирает `bdv [id] [--db <path>]`.
- Перед запуском TUI проверяет, что `bd` есть в `PATH`, иначе печатает сообщение и выходит с кодом 1.
- Если не задан ни `--db`, ни `BEADS_DIR`, ни `BEADS_DB`, ищет `.beads` от текущей папки вверх. Если не нашёл, печатает сообщение с подсказкой `bd init` и выходит с кодом 1. Остальные проблемы (например, Dolt-сервер не нашёл базу) не угадываются заранее: их показывает экран ошибки внутри TUI.
- Запускает программу в alt screen.

### Раскладка клавиш

| Контекст | Клавиши |
|---|---|
| Дерево | `↑↓`/`j k` перемещение · `→`/`l` раскрыть · `←`/`h` свернуть или к родителю · `Enter`/`Space` раскрыть или свернуть · `g`/`G` в начало или в конец |
| Карточка | `↑↓`/`j k` прокрутка · `PgUp`/`PgDn` по страницам · `1`–`9` переход по связи (работает в любом фокусе) |
| Поиск | `/` открыть · печать фильтрует сразу · `Enter` закрепить · `Esc` сбросить |
| Глобально | `Tab` фокус · `r` обновить · `c` закрытые · `e` события · `y` копировать ID · `?` справка · `q`/`Ctrl+C` выход |
| Узкий режим | `Enter` открыть карточку · `Esc` назад к дереву |

## Testing Decisions

- **Хороший тест проверяет внешнее поведение**: что видит и может сделать пользователь (какие задачи видны, что выбрано, что написано в карточке и статус-строке). Внутренние поля модели и порядок вызовов он не проверяет. Тесты переживают рефакторинг внутренностей.
- **Основной шов один: процесс `bd` + сообщения в модель приложения.** Тест кладёт в `PATH` поддельный `bd` (shell-скрипт). Скрипт по аргументам отдаёт JSON-фикстуры, пишет полученные аргументы в файл и умеет падать с заданным stderr и кодом. Модель приложения создаётся как в реальном запуске, ей отправляются сообщения (нажатия клавиш, размер окна, тик таймера), команды Bubble Tea выполняются синхронно в тестовом помощнике. Проверяются наблюдаемые вещи: ID видимых строк, выбранный ID, фокус, вхождение текста в `View()`. Так один шов покрывает и разбор контракта `bd`, и дерево, и клавиши, и обработку ошибок.
- **Фикстуры** написаны вручную по реальной схеме `bd` v0.59, без личных данных. Они покрывают: эпик с подзадачами в разных статусах, закрытый эпик с открытым ребёнком, `event`-детей, блокировку `blocks`, задачу с `parent` вне выборки, задачу с комментариями, кириллические заголовки и вторую версию списка для сценариев обновления (изменилась задача, исчезла задача, добавилась задача).
- **Модель дерева и карточка** — чистые функции без процессов и терминала, их тестируем напрямую: сортировку, видимость, поиск, `Nearest`, секции и нумерацию ссылок. Через основной шов проверять сотни комбинаций было бы громоздко. Всё, что связано с клавишами, обновлением, кешем и ошибками, проверяется только через основной шов.
- **Prior art**: внешние утилиты подменяются скриптами в `PATH` внутри sandbox-помощника, а тесты читают записанные аргументы. Это распространённый приём для CLI-обёрток.
- **Не тестируем автоматически**: точный внешний вид (цвета, рамки, Glamour-рендер), поведение мыши, реальный буфер обмена. Это проверяется вручную по чек-листу в документации. Для копирования тестируется только то, что вызвана команда копирования с нужным ID: через подменный `pbcopy` в `PATH`.

## Out of Scope

- Любые изменения задач, кроме добавления комментария (v1.1): статус, приоритет, закрытие, создание, редактирование в `$EDITOR`.
- Несколько проектов в одном окне и переключение между ними.
- Фильтры по статусу, label, assignee и приоритету (кроме переключателей `c` и `e` и текстового поиска).
- Граф зависимостей, метрики, triage, критический путь: это область `bv`.
- Дерево по зависимостям `blocks` (они только в карточке).
- Слежение за файлами `.beads` (fsnotify): с Dolt-сервером ненадёжно, вместо этого опрос.
- Чтение базы в обход CLI `bd`.
- Настраиваемые клавиши, темы и конфиг-файл.
- Snapshot-тесты рендера.

## Further Notes

- `bv` (beads_viewer) — существующий полнофункциональный просмотрщик. `bdv` осознанно его не заменяет: это минималистичная альтернатива из одного экрана.
- Проект, в котором `bd` падает с ошибкой Dolt «database not found», — хороший живой сценарий для ручной проверки экрана ошибки.

## v1.1: группы, статусы, дизайн, комментарии

Решения пользователя от 2026-11-19 после ручной проверки v1. Где v1.1 противоречит разделам выше, действует v1.1.

### Группы по приоритету

- По умолчанию корневые задачи собраны под заголовками групп `P0`…`P4`. Заголовок выглядит так: маркер раскрытия, `P<n>` в цвете приоритета и `· <число видимых задач группы>`. Внутри группы сохраняется прежняя сортировка: статус, затем дата создания, затем ID.
- Подзадачи остаются под своим родителем, даже если их приоритет отличается. В группу попадает только корень ветки.
- Пустые группы (после фильтров и поиска) не показываются. Задача с приоритетом вне 0–4 попадает в группу со своим номером, группы идут по возрастанию.
- Заголовки групп сворачиваются и раскрываются так же, как узлы: `←/h`, `→/l`, `Space`, `Enter`. По умолчанию раскрыты все группы. Свёрнутое состояние группы переживает обновление.
- Курсор может стоять на заголовке группы. Тогда в карточке показывается сводка группы: число задач по статусам.
- Клавиша `p` включает и выключает группировку. Без неё дерево работает как в v1.
- Поиск и переходы по цифрам учитывают группы: группа раскрывается, если нужная задача внутри.

### Статусы

- Иконки статусов цветные, цвета адаптивные: in_progress жёлтый, blocked красный, deferred голубой, closed зелёный, open обычный.
- В карточке статус показан бейджем: `ОТКРЫТА`, `В РАБОТЕ`, `БЛОК`, `ОТЛОЖЕНА`, `ЗАКРЫТА`, неизвестный статус в верхнем регистре. Бейдж закрашен цветом статуса.
- В верхней строке сводка по статусам видимого проекта, она же служит легендой: `◐ 2 в работе · ○ 5 открыто · ● 0 блок · ✓ 21 закрыто` (нулевые группы, кроме блокированных, можно скрыть).
- Статус-строка внизу стала понятнее:
  - слева время `обновлено ЧЧ:ММ:СС` либо ошибка с `⚠` красным;
  - затем активные режимы словами: `закрытые`, `события`, `без групп`, `фильтр: <q>`;
  - справа подсказки клавиш, сокращаемые по ширине: `/ поиск · m комментарий · ? справка`.

### Дизайн

- Сверху строка: имя проекта (папка, в которой лежит `.beads`) и сводка статусов.
- Обе панели в скруглённых рамках. Заголовок панели вписан в верхнюю границу. Рамка активной панели акцентного цвета, неактивной приглушённая.
- Выбранная строка подсвечена фоном акцентного цвета на всю ширину панели.
- В дереве ID показывается без общего префикса проекта: `fjpw` вместо `acme-shop-fjpw`, если у всех задач один префикс `<x>-`. В карточке ID всегда полный.
- В узком режиме та же рамка вокруг единственной панели.

### Карточка

Сейчас ID повторяется дважды (в заголовке панели и в шапке), а все секции выглядят одинаково. Новый вид:

- Полный ID только в рамке панели. Первой строкой карточки идёт заголовок задачи жирным, с переносом.
- Под заголовком строка метаданных из «чипов»: бейдж статуса, `P1` в цвете приоритета, тип задачи приглушённой рамочкой или в скобках, `@assignee`.
- Labels идут отдельной строкой как цветные чипы `#batch:01`. Даты одной приглушённой строкой.
- Заголовки секций акцентного цвета с тонкой линией до края панели, например `Description ─────────`. Между секциями одна пустая строка.
- Связи (Parent, Children, Blocked by, Blocks, Related) выводятся строками `[1] ◐ P1 id  Заголовок`. Номер связи и иконка статуса цветные, ID приглушённый, заголовок обычный.
- Комментарии:
  - автор жирным;
  - дата и время приглушённо;
  - текст с отступом и вертикальной чертой слева `▏`;
  - между комментариями одна пустая строка.
- Предупреждение (Notice) показывается жёлтой строкой со знаком `⚠`.
- Ширина всех строк не больше ширины панели. Перенос по словам, как в F3.
- Справка рисуется в рамке и по-прежнему помещается в 80x24.

### Комментарии (первая запись в bd)

- Клавиша `m` (вне режима ввода и справки, при выбранной задаче) открывает внизу экрана многострочное поле `Комментарий к <id>:` высотой около 5 строк. Панели над ним укорачиваются.
- `Ctrl+S` отправляет комментарий, `Esc` закрывает поле. Черновик для этой задачи сохраняется в памяти до отправки или выхода.
- Пустой текст или текст из одних пробелов не отправляется.
- Отправка идёт командой `bd [--db P] comments add <id> -f <временный файл>` **без** `--readonly`. Файл используется, чтобы не было проблем с кавычками, длиной и текстом, начинающимся с `-`. Таймаут 15 с. Временный файл удаляется в любом случае.
- Пока идёт отправка, поле заблокировано и показывает `отправка…`.
  - При успехе поле закрывается, появляется подтверждение `комментарий добавлен`, кеш комментариев задачи сбрасывается, комментарии загружаются заново и обновляется список.
  - При ошибке текст остаётся в поле, под ним выводится первая строка ошибки `bd`.
- Все остальные вызовы `bd` по-прежнему идут с `--readonly`. Комментарий — единственная запись.

### Инициализация проекта (`bd init`)

- Если базы beads нет, `bdv` предлагает создать её. Это происходит в двух случаях: preflight не нашёл `.beads`, или первая загрузка упала со stderr `bd`, содержащим `no beads database found`. Сам `bdv` ничего не создаёт.
- Предложение показывается только когда не заданы `--db`, `BEADS_DIR` и `BEADS_DB`: иначе непонятно, где создавать базу. В остальных случаях работает прежнее поведение (сообщение и выход или экран ошибки).
- Экран: `No beads database in this project.` / `В этом проекте нет базы beads.`, ниже `i — initialize (bd init) · q — quit`. Ошибка `bd` (stderr) остаётся видна.
- `i` открывает подтверждение: `Initialize beads in <путь к текущей папке>?`, строка `prefix: <имя текущей папки>`, внизу `y — run bd init · n — cancel`. Сработать может только `y`, любые другие клавиши кроме `q`/`Ctrl+C` отменяют.
- Запускается ровно `bd init` в текущей папке, без `--readonly` и без дополнительных флагов (поведение `bd` по умолчанию: префикс равен имени папки, ставятся хуки). stdin пустой, таймаут 120 с, контекст корневой (отменяется при выходе).
- Пока команда работает, показывается `initializing…` / `инициализация…`.
  - Успех: показ последних строк вывода `bd init` (очищенных) и автоматическая загрузка списка. Новый проект откроется с пустым деревом `No tasks`.
  - Ошибка: экран с очищенным stderr, `i` позволяет повторить.
- Это вторая и последняя пишущая команда наряду с `comments add`.

### v1.2: копирование, зависимости, последовательные ID

Решения пользователя от 2026-11-20.

**Копирование**
- `y` копирует ID, `Y` — заголовок, `D` — описание (исходный markdown), `M` — всю карточку как markdown (заголовок, ID, статус, приоритет, тип, description, notes).
- Тост пишет, что именно скопировано: `copied ID: …`, `copied title`, `copied description`, `copied card`, на русском аналогично. Если копировать нечего (пустое описание, выбран заголовок группы), появляется тост `nothing to copy` / `нечего копировать`.
- Клавиша `S` переключает перехват мыши.
  - Перехват выключен: в терминале работает обычное выделение текста, колесо мыши панели не прокручивает. В статус-строке пометка `mouse off` / `мышь выкл`.
  - Перехват включён (по умолчанию): поведение v1.1.
- В справке и README сказано, что выделять текст можно и при включённом перехвате: Shift+мышь в Ghostty/iTerm2, Fn+мышь в Terminal.app.

**Зависимости**
- Задача заблокирована, если у неё есть зависимость `blocks` на задачу со статусом не `closed`.
- У заблокированной задачи в строке дерева перед заголовком стоит красный знак `⊘`.
- В сводке наверху добавляется счётчик `⊘ N waiting` / `⊘ N ждут`, если N > 0.
- Клавиша `R` включает фильтр «готовы к работе»: в дереве остаются только незаблокированные задачи, родители заблокированных показываются как контекст. В статус-строке пометка `ready` / `готовые`. Поиск, группы и переключатели `c`/`e` с фильтром совместимы.
- Блокеры вычисляются по полю `dependencies` из `bd list` и статусам задач из того же списка. Блокер, которого нет в выборке, считается открытым.
- Вложенность заблокированной задачи под блокер **не делаем**: задача появлялась бы в дереве дважды, а связи и так видны в карточке (`Blocked by`/`Blocks`) и через `⊘`.

**Последовательные ID при `bd init`**
- В диалоге подтверждения `bd init` есть строка `IDs: hash (bd default)` / `ID: хеш (по умолчанию bd)`. Клавиша `c` переключает её на `IDs: sequential 1, 2, 3` / `ID: последовательные 1, 2, 3`.
- Если выбраны последовательные ID, после успешного `bd init` выполняется `bd config set issue_id_mode counter` (режим `bd`, GH#2002), это третья пишущая команда. Ошибка этой команды показывается, но база остаётся созданной.
- По умолчанию используется хеш, как у `bd`.

### v1.3: настройки beads

Решения пользователя от 2026-11-20. Ключи сверены с документацией https://beads.gascity.com/reference/configuration и с локальным `bd` 0.59. Документация описывает более новую версию: ключи, которых нет в 0.59, не показываем.

**Экран**
- Клавиша `,` открывает экран настроек: панель в рамке на всё окно с заголовком `Settings · <project>` / `Настройки · <project>`. Работает вне режима ввода и справки, только когда база есть.
- Настройки разбиты на секции. `j/k` выбирают строку, `Enter`/`Space` меняют значение, `Esc` возвращает к дереву. Под выбранной строкой выводится краткое описание и ключ `bd`, например `issue_id_mode`.
- Типы значений:
  - **bool** — переключатель;
  - **enum** — перебор вариантов;
  - **int/float** — поле ввода с проверкой диапазона;
  - **list** — редактор списка: добавить, удалить; встроенные элементы показаны только для чтения.
- Любое изменение сначала показывает подтверждение `<key>: <старое> → <новое>`, применяется только по `y`. Для опасных ключей в подтверждении есть дополнительное предупреждение.
- Запись идёт командой `bd [--db P] config set <key> <value>`, сброс к умолчанию — `bd config unset <key>`. Обе команды без `--readonly`. Таймаут 15 с. После записи значение перечитывается, ошибка показывается под строкой.
- Чтение:
  - ключи базы — одним вызовом `bd --readonly config list --json`;
  - YAML-ключи — `bd --readonly config get <key> --json` параллельно;
  - типы — `bd --readonly types --json`.
  
  Пока идёт загрузка, видно `loading settings…`. Ключ, который `bd` не знает (ошибка get), в списке не показывается.
- Значение по умолчанию (ключ не задан) показывается приглушённо с пометкой `(default)`.

**Секции и ключи**
1. **IDs / ID задач**
   - `issue_prefix` — только чтение, подсказка «меняется командой `bd rename-prefix`».
   - `issue_id_mode` — enum `hash|counter`. Предупреждение: действует только на новые задачи, старые ID не меняются.
   - `min_hash_length`, `max_hash_length` — int 3–10, min ≤ max; показываются только в режиме `hash`.
   - `max_collision_prob` — float 0.01–0.50, в Advanced.
2. **Statuses & types / Статусы и типы**
   - `status.custom` — список; встроенные `open, in_progress, blocked, deferred, closed` показаны только для чтения.
   - `types.custom` — список; встроенные из `bd types --json` показаны только для чтения.
   - При удалении элемента, которым пользуются задачи из текущего списка, в подтверждении выводится предупреждение с числом таких задач.
3. **Creating issues / Создание задач**
   - `create.require-description` — bool.
   - `validation.on-create`, `validation.on-close` — enum `none|warn|error`.
   - `hierarchy.max-depth` — int 1–10.
4. **Storage (advanced) / Хранилище (расширенные)**
   - `dolt.auto-commit` — enum `on|off|batch`. Для `off` и `batch` предупреждение про незакоммиченные изменения.
   - `dolt.auto-push` — bool, предупреждение «нужен remote; одновременный push может повредить данные».
   - `export.auto` — bool.
   - `backup.enabled` — bool.
   - `compaction_enabled`, `auto_compact_enabled` — bool.
   - `compact_tier1_days`, `compact_tier2_days` — int ≥ 1.
- Никогда не показываются как редактируемые: `schema_version`, `db`, `actor`, `identity`, секреты (`*token*`, `*key*`, `*secret*`, `*password*`), `sync.remote`, `federation.*`.
- Запускать компакцию и `rename-prefix` из настроек нельзя.

### v1.4: вкладки, спеки, карточка группы

Решения пользователя от 2026-11-20.

**Карточка группы приоритета.** Если выбран заголовок `P<n>`, правая панель показывает не только сводку, но и список задач группы, учитывая текущие фильтры. Каждая строка: `[n] <иконка> <id>  <заголовок>`, ⊘ у ждущих. Порядок как в дереве. Первые девять задач нумеруются, и по цифре можно на них перейти.

**Поля спеки в карточке задачи.** Если у задачи заполнены `spec_id`, `design` или `acceptance_criteria` (они приходят из `bd show --json`), карточка показывает секции `Spec` (путь или ссылка, одной строкой), `Design` и `Acceptance` (markdown). Названия секций английские в обоих языках, как у остальных секций.

**Вкладки.** Под верхней строкой идёт строка вкладок `Tasks │ Specs N │ Decisions N │ Memory N │ Formulas N`. Активная вкладка выделена, пустые приглушены. `[` и `]` переключают вкладки по кругу (вне режима ввода, справки, комментария, настроек и экранов init). Выбор и раскрытие в каждой вкладке запоминаются отдельно.
- **Tasks** — дерево как раньше.
- **Specs** — задачи типа `epic`, кроме шаблонов с меткой `template`. Это формат, в котором скилл to-spec публикует спеку: спека лежит в описании эпика, тикеты — его дети. В строке иконка статуса, ID, заголовок и прогресс `███░░ 3/5` по прямым детям, где учитываются закрытые. В карточке описание целиком (спека), прогресс в чипах и секция `Tickets` со всеми детьми и их статусами, нумерованными для перехода. Переход цифрой переключает на вкладку Tasks и выбирает тикет. Фильтры `c` (закрытые) и `/` (поиск) работают, группы P здесь не применяются.
- **Decisions** — задачи типа `decision`, плоский список, карточка обычная. Фильтры `c` и `/` работают.
- **Memory** — `bd --readonly memories --json` (в 0.59 это объект `ключ → текст`). Слева ключи, справа текст как markdown. Пусто — `No memories` / `Памяти нет`. Только чтение.
- **Formulas** — `bd --readonly formula list --json` (в 0.59 возвращает `null`, если формул нет) и шаблоны: эпики с меткой `template` из `bd list --include-templates`. Слева имена, справа описание. Только чтение, запускать формулы из bdv нельзя.
- Memory и Formulas загружаются при первом открытии вкладки и обновляются по `r`. Ошибка загрузки показывается в панели, остальные вкладки продолжают работать.

**Комментарии.** Отправка только по `Ctrl+S`. Альтернатива `Alt+Enter` убрана: быстрые Esc+Enter терминал склеивает в Alt+Enter, и комментарий мог уйти при отмене. Bubble Tea в raw-режиме отключает XON/XOFF, поэтому `Ctrl+S` доходит до программы.

### Язык интерфейса

- По умолчанию интерфейс на английском. Русский включается, если `LC_ALL`, `LC_MESSAGES` или `LANG` (первая непустая переменная по этому порядку) начинается с `ru`. Переменная `BDV_LANG=en|ru` имеет приоритет над локалью.
- Все тексты интерфейса лежат в одном пакете-каталоге строк: заголовки, статус-строка, справка, ошибки, бейджи статусов, `--help`, сообщения preflight. В коде строк интерфейса не остаётся, поэтому новый язык добавляется одним файлом.
- Английские тексты: `Tasks`, `updated HH:MM:SS`, `update failed: …`, `copied: <id>`, `No open tasks — press c to show closed`, `No tasks`, `Nothing found: <q>`, `bd exited with an error`, `r — retry · q — quit`, `bd did not respond in N s`, `Loading tasks…`. Бейджи статусов: `OPEN`, `IN PROGRESS`, `BLOCKED`, `DEFERRED`, `CLOSED`. Сводка: `◐ 2 in progress · ○ 5 open · ● 0 blocked · ✓ 21 closed`. Комментарии: `Comment on <id>:`, `Ctrl+S send · Esc cancel`, `sending…`, `comment added`. Справка повторяет русскую по смыслу.
- Тесты фиксируют язык явно: харнесс по умолчанию работает на английском, отдельные тесты проверяют русский.
- README на английском. Спека, чек-лист и комментарии в коде остаются на русском.
