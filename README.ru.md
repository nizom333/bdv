# bdv

**bdv — быстрый минималистичный терминальный интерфейс (TUI) для трекера задач [beads](https://github.com/steveyegge/beads) (`bd`): смотрите в реальном времени дерево задач, которое вы и ваши ИИ-агенты для программирования (Claude Code, Codex, Cursor и другие) ведёте в beads, из соседнего терминала.**

В верхней строке — имя проекта и сводка по статусам, под ней — вкладки. Ниже слева дерево задач по связям родитель–потомок, справа полная карточка выбранной задачи, внизу строка статуса. Данные обновляются сами каждые 10 секунд, поэтому bdv можно держать открытым, пока агент создаёт, меняет и закрывает задачи. Интерфейс на снимке английский; с `BDV_LANG=ru` те же строки по-русски.

bdv бережно обращается с данными. Записей всего несколько: комментарий (`m`), который уходит как `bd comments add <id> -f <временный файл>`; `bd init` в проекте без базы; `bd config set issue_id_mode counter` сразу после этого `bd init`, если выбраны последовательные ID; `bd config set` / `bd config unset` с экрана настроек (`,`), каждая запись — после подтверждения `y`. Все остальные вызовы `bd` идут с `--readonly`.

## Возможности

- **Дерево задач** по связям родитель–потомок: открытые сверху, закрытые и события скрыты, пока не попросите (`c`, `e`), ID без общего префикса проекта.
- **Группы по приоритету**: корневые задачи под заголовками `P0`…`P4` (`p` включает и выключает); карточка группы перечисляет её задачи.
- **Вкладки**: Tasks, Specs (эпики с прогрессом `███░░░░░ 3/8`), Decisions, Memory (`bd memories`) и Formulas (`bd formula list` и шаблоны).
- **Карточка задачи**: описание в markdown, заметки, поля спеки (Spec, Design, Acceptance), родитель, дети, блокеры, связанные задачи и комментарии; `1`–`9` переходят по ссылкам.
- **Поиск**, который фильтрует по мере набора, в том числе по кириллице.
- **Заблокированные задачи** помечены красным `⊘` и посчитаны в верхней строке; `R` оставляет только готовые к работе.
- **Комментарии**: `m` — написать, `Ctrl+S` — отправить.
- **Экран настроек bd** (`,`): чтение и изменение `bd config` проекта с подтверждением каждого изменения.
- **`bd init`** в папке без базы, с хеш-ID или последовательными ID.
- **Копирование** ID, заголовка, описания или всей карточки в markdown (`y`, `Y`, `D`, `M`).
- **Языки**: английский и русский интерфейс (`BDV_LANG`).
- Колесо мыши, узкий режим для маленьких окон, светлая и тёмная темы терминала.

## Установка

bdv читает всё через CLI `bd`, поэтому сначала установите [beads](https://github.com/steveyegge/beads) и проверьте, что `bd` есть в `PATH`.

### Homebrew (macOS, Linux)

```sh
brew install nizom333/tap/bdv
```

В тапе bdv лежит как Homebrew cask с готовыми бинарниками для macOS и Linux (amd64, arm64). Обновление: `brew upgrade bdv`.

### Scoop (Windows)

```powershell
scoop bucket add nizom333 https://github.com/nizom333/homebrew-tap
scoop install nizom333/bdv
```

### Debian, Ubuntu, Fedora, RHEL, Alpine

Скачайте пакет для своей системы из [последнего релиза](https://github.com/nizom333/bdv/releases/latest). Имена файлов (`VERSION` без `v`, например `0.1.0`):

| Формат | amd64 | arm64 |
|---|---|---|
| deb | `bdv_VERSION_amd64.deb` | `bdv_VERSION_arm64.deb` |
| rpm | `bdv-VERSION-1.x86_64.rpm` | `bdv-VERSION-1.aarch64.rpm` |
| apk | `bdv_VERSION_x86_64.apk` | `bdv_VERSION_aarch64.apk` |

```sh
VERSION=0.1.0
curl -LO "https://github.com/nizom333/bdv/releases/download/v${VERSION}/bdv_${VERSION}_amd64.deb"
sudo apt install "./bdv_${VERSION}_amd64.deb"                 # Debian, Ubuntu
# sudo dnf install "./bdv-${VERSION}-1.x86_64.rpm"            # Fedora, RHEL
# sudo apk add --allow-untrusted "./bdv_${VERSION}_x86_64.apk" # Alpine
```

### Arch Linux (AUR)

Скоро: `bdv-bin` (`yay -S bdv-bin`). Пока используйте бинарник из релиза или `go install`.

### Go

```sh
go install github.com/nizom333/bdv@latest
```

Бинарник `bdv` появится в `$(go env GOPATH)/bin`; `bdv --version` показывает версию модуля.

### Бинарники

В каждом [релизе](https://github.com/nizom333/bdv/releases) есть архивы для macOS, Linux и Windows на amd64 и arm64: `bdv_VERSION_OS_ARCH.tar.gz` (`.zip` для Windows), например `bdv_0.1.0_darwin_arm64.tar.gz`, и `checksums.txt`:

```sh
sha256sum --ignore-missing -c checksums.txt   # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf bdv_0.1.0_linux_amd64.tar.gz && sudo mv bdv /usr/local/bin/
```

### Из исходников

Нужен Go (версия — в `go.mod`).

```sh
git clone https://github.com/nizom333/bdv && cd bdv
make install                     # в ~/.local/bin
make install PREFIX=/usr/local   # в другое место
```

Если `~/.local/bin` нет в `PATH`, добавьте `export PATH="$HOME/.local/bin:$PATH"` в `~/.zshrc`.

## Использование

```sh
cd <проект> && bdv          # .beads ищется в текущей папке и выше (до $HOME)
bdv <id>                    # открыть сразу на задаче
bdv --db <путь>             # явная база (как у bd)
bdv --help | --version
```

Обычная схема: ИИ-агент вроде Claude Code работает по задачам beads в одном терминале, а bdv показывает дерево в другом — видно, что в работе, что заблокировано и что сделано, без вопросов агенту.

### Проект без базы

Если базы beads ещё нет (нет `.beads` в текущей папке и выше, или `bd` отвечает `no beads database found`), bdv не выходит, а предлагает её создать: нажмите `i`, проверьте папку и префикс в подтверждении, затем `y` — в текущей папке запустится обычный `bd init` с настройками bd по умолчанию (префикс — имя папки). В подтверждении виден и режим ID, `IDs: hash (bd default)`; `c` переключает на `IDs: sequential 1, 2, 3` и обратно. С последовательными ID после успешного `bd init` выполняется `bd config set issue_id_mode counter`; если эта команда не удалась, показывается её ошибка, а дерево всё равно открывается, потому что база уже есть. Любая другая клавиша отменяет. После успеха открывается пустое дерево. `~/.beads` — глобальная папка данных bd, а не проект, поэтому базой здесь не считается. Предложение появляется, только если не заданы `--db`, `BEADS_DIR` и `BEADS_DB`: иначе непонятно, где должна быть база.

### Настройки

`,` открывает настройки bd проекта по секциям: ID (префикс, режим ID, длины хеша), статусы и типы (свои списки), создание задач (обязательное описание, проверка, глубина вложенности) и хранилище (авто-коммит и авто-пуш Dolt, экспорт JSONL, резервные копии, сжатие). Значения читаются через `bd --readonly config list --json`, `bd --readonly config get <ключ> --json` и `bd --readonly types --json`; незаданное значение приглушено и помечено `(default)`. `j k` двигают выбор, строка под выбранной настройкой описывает её и называет ключ `bd`, `Esc` возвращает к дереву.

`Enter` (или `Space`) меняет выбранное значение: логические переключаются, варианты идут по кругу, для чисел открывается поле с проверкой диапазона, а для своих статусов и типов — редактор, где `a` добавляет имя (`a-z`, `0-9`, `_`), `x` (или `d`) удаляет выбранное, `Enter` сохраняет список; встроенные статусы и типы видны, но не удаляются. `u` сбрасывает заданное значение (`bd config unset`). Каждое изменение сначала показывает `<ключ>: <было> → <станет>`, с предупреждением для рискованных ключей (режим ID, авто-коммит и авто-пуш Dolt, проверка `error`, удаление статуса или типа, который ещё используют задачи), и выполняется только по `y`. Префикс ID только для чтения: его меняет `bd rename-prefix`. Секреты, `schema_version`, `db`, `actor`, `identity`, `sync.remote` и `federation.*` не показываются никогда. Настройка из `config.yaml` видна, только если `bd config get` сообщает о ней как о файловой (`location: config.yaml`); иначе этот bd не считает её настройкой файла, и запись оставила бы в базе неиспользуемый ключ, поэтому она скрыта (в bd 0.59 это `export.auto`). Свои типы читаются в любом случае. Если часть значений не прочиталась, строка говорит сколько, а `r` читает их снова. Показаны значения, которые сообщает bd, поэтому переменные `BD_*` или глобальный конфиг (`~/.config/bd/config.yaml`) могут перекрывать то, что записано в файле проекта.

### Вкладки

`[` и `]` переключают вкладки по кругу: `Tasks │ Specs N │ Decisions N │ Memory N │ Formulas N`. Активная подсвечена, пустые приглушены. Каждая вкладка помнит свой выбор, прокрутку и поиск; раскрытые ветки и группы дерева остаются как были. `Tab`, прокрутка карточки, копирование, комментарии и `1`–`9` работают везде одинаково; `R`, `p` и `e` действуют только в Tasks, а `c` и `/` — в Tasks, Specs и Decisions. В строке статуса — клавиши текущей вкладки.

```text
╭─ ◆ Specs (2) ─────────────────────────╮╭─ demo-app-k3f ──────────────────────────────────────────────╮
│ ◐ k3f Checkout flow       ██░░░░░░ 1/4││ Checkout flow                                               │
│ ○ p7a Product search      ░░░░░░░░ 0/2││  IN PROGRESS   P1  [epic]  ██░░░░░░ 1/4                     │
```

- **Tasks** — дерево, описанное выше.
- **Specs** — эпики, кроме шаблонов (эпиков с меткой `template`): так публикует спеку навык to-spec — спека в описании эпика, тикеты — его дети. В строке иконка статуса, ID, заголовок и прогресс по прямым детям, `███░░░░░ 3/8` (закрытые из всех; события не считаются). Карточка показывает описание целиком, прогресс среди чипов и секцию `Tickets` со всеми тикетами и их статусами; `1`–`9` переключают на Tasks и выбирают тикет. Группы по приоритету здесь не действуют.
- **Decisions** — задачи типа `decision` плоским списком с обычной карточкой.
- **Memory** — `bd memories` (ключ слева, текст справа в markdown), `No memories`, если записей нет.
- **Formulas** — `bd formula list` и шаблоны (эпики с меткой `template` и молекулы-шаблоны bd из `bd list --include-templates`): имена слева, описание справа. bdv никогда не запускает формулы.

Memory и Formulas читаются через `bd --readonly memories --json`, `bd --readonly formula list --json` и `bd --readonly list --include-templates --flat --json --all -n 0` при первом открытии вкладки и снова по `r` на ней. Ошибка чтения показывается в панели; остальные вкладки продолжают работать.

## Клавиши

| Где | Клавиши |
|---|---|
| Дерево | `↑↓`/`j k` движение · `→`/`l` раскрыть · `←`/`h` свернуть или к родителю · `Enter`/`Space` раскрыть или свернуть · `g`/`G` в начало или конец |
| Карточка | `↑↓`/`j k` прокрутка · `PgUp`/`PgDn` страница · `1`–`9` переход по ссылке (из любого фокуса; из Specs и Decisions открывает Tasks) |
| Поиск | `/` открыть · набор сразу фильтрует · `Enter` закрепить · `Esc` сбросить |
| Комментарий | `m` написать комментарий к выбранной задаче · `Ctrl+S` отправить · `Esc` закрыть, черновик сохраняется |
| Везде | `Tab` фокус · `[`/`]` вкладки · `r` обновить (в Memory и Formulas — перечитать вкладку) · `c` закрытые · `e` события · `p` группы по приоритету · `R` только готовые · `,` настройки bd · `?` справка · `q`/`Ctrl+C` выход |
| Настройки | `,` открыть · `j k` движение · `Enter`/`Space` изменить · `u` сбросить к умолчанию · `y` подтвердить · `Esc` назад к дереву |
| Копирование | `y` ID · `Y` заголовок · `D` описание (исходный markdown) · `M` карточка в markdown (заголовок, ID, статус, приоритет, тип, описание, заметки) |
| Мышь | колесо двигает курсор или прокручивает · `S` выключает и включает захват мыши |
| Узкий режим | `Enter` открыть карточку · `Esc` назад к дереву |
| Без базы | `i` предложить `bd init` · `c` переключить ID: хеш или последовательные · `y` запустить · `r` повторить · `q` выход |

`?` показывает тот же список внутри bdv, `bdv --help` печатает его.

Колесо мыши прокручивает панель под курсором (над деревом двигает выбор); клики игнорируются.

Задача ждёт (заблокирована), если она сама не закрыта и у неё есть зависимость `blocks` от незакрытой задачи; блокер, которого нет в `bd list`, считается открытым. Закрытая задача не ждёт никогда, какие бы у неё ни были блокеры. У ждущих задач в дереве красный `⊘` перед заголовком, в верхней строке добавляется `⊘ N waiting` (по задачам, видимым при текущих `c`/`e`), а в карточке под чипами статуса — `⊘ waiting on N open blockers`. `R` оставляет только задачи, готовые к работе (не заблокированные); родители готовых задач остаются приглушённым контекстом. Фильтр сочетается с поиском, группами и `c`/`e`, в строке статуса — `ready`. Заблокированные задачи не вкладываются под блокеры: связи показаны в секциях карточки `Blocked by`/`Blocks`.

Карточка показывает заголовок, чипы статуса, метки и даты, затем секции с содержимым: `Description`, `Notes` и поля спеки из `bd show` — `Spec` (путь или ссылка из `--spec-id`), `Design` и `Acceptance` (markdown), — а за ними `Parent`, `Children`, `Blocked by`, `Blocks`, `Related` и `Comments`. Названия секций на всех языках остаются английскими.

Группы по приоритету (`p`) собирают корневые задачи под заголовками `P0`…`P4`. Когда выбран заголовок, карточка показывает число задач в группе, сводку по статусам и секцию `Tasks` со списком в порядке дерева, `[n] иконка id  заголовок` (красный `⊘` отмечает ждущие); список следует за `c`, `e`, `R` и поиском, `1`–`9` переходят к первым девяти.

Копирование кладёт в буфер обмена текст в том виде, в каком его хранит `bd`, вместе с markdown; убираются только управляющие символы. Всплывающее сообщение говорит, что скопировано (`copied ID: …`, `copied title`, `copied description`, `copied card`), или `nothing to copy`, если описание пустое или выбран заголовок группы.

Чтобы выделить текст мышью, пока bdv её захватывает, держите Shift и тяните (Ghostty, iTerm2) или Fn и тяните (Terminal.app). Либо нажмите `S`, чтобы выключить захват мыши: обычное выделение терминала работает, колесо больше не прокручивает панели, а в строке статуса `mouse off`, пока вы снова не нажмёте `S`. Пока захват выключен, bdv отключает и режим alternate scroll терминала (DECSET 1007), чтобы колесо не превращалось в стрелки, двигающие курсор; он включается обратно следующим `S` и при выходе.

## Настройка и язык

Своего конфиг-файла у bdv нет. Базу он ищет так же, как `bd`: `--db <путь>`, затем `BEADS_DIR` / `BEADS_DB`, затем `.beads` в текущей папке и выше. Настройки проекта хранятся в bd и меняются с экрана настроек (`,`).

Интерфейс по умолчанию английский. Он переключается на русский, если локаль начинается с `ru`: берётся первая непустая из `LC_ALL`, `LC_MESSAGES`, `LANG`. `BDV_LANG=en` или `BDV_LANG=ru` важнее локали.

```sh
BDV_LANG=ru bdv
```

## Почему не bv?

[beads_viewer](https://github.com/Dicklesworthstone/beads_viewer) (`bv`) — отличный и богатый возможностями просмотрщик beads, с графовой аналитикой и куда большим числом видов, чем когда-либо будет у bdv. Если они вам нужны — берите bv. bdv нацелен на меньшее: один экран, дерево и карточка, быстрый старт и строго read-only взгляд на данные `bd`, кроме нескольких подтверждаемых записей, перечисленных выше. Его место — в соседней панели рядом с агентом, где он не мешает. Оба прекрасно уживаются вместе.
